PART A — NOTES

1. Project Overview

1.1 The problem

Small businesses put a website online and then lose customers on it. A visitor has a simple question — "Do you deliver to my area?", "What time do you open?" — and there is nobody to answer at 11 PM. The visitor leaves and buys somewhere else. Hiring a person to sit on live chat 24 hours a day is too expensive for a small shop.

1.2 The solution

WebtiqAI is an AI chatbot that a business can embed on its own website. The owner types the business information once (FAQs, prices, timings, policies). That information becomes the bot's Knowledge Base. After that the bot answers visitors instantly, at any hour, using only that information.

One-line definition (memorise this) WebtiqAI is an embeddable AI chatbot that answers website visitors 24/7 using only the business's own content, and converts the questions it cannot answer into leads for the human team.

1.3 Why "only its own content" matters

A normal chatbot built on a language model will happily invent an answer when it does not know something. This is called hallucination. For a business that is dangerous — the bot could promise free delivery that does not exist. So this project forces the AI to answer only from the given content, and to say NO_ANSWER when the content does not cover the question. That single rule is the heart of the project.

4.1 Separation of concerns

Each file has one job. This is a design principle examiners like to hear about:

FileSingle responsibility
index.htmlStructure — what content exists on the page
style.cssPresentation — how that content looks
script.jsBehaviour — what happens when the user acts
api.jsCommunication — all network calls in one place
server.jsBusiness rules + secrets — the parts the user must not see
Why api.js is a separate file If the backend URL or an endpoint name changes, only api.js needs editing. The two page scripts simply call Api.chat(...) and do not care how the request is made. This is called abstraction.

4.2 Files that must never be shared

  • server/.env — contains the secret API key. Anyone with it can spend your OpenAI credit.
  • server/node_modules/ — thousands of files; rebuilt instantly with npm install.
  • server/data/ — may contain real visitor questions and contact details.

All three are listed in .gitignore, which tells Git to ignore them.

5.3 Important attributes used

  • id — a unique hook for JavaScript, e.g. id="contactForm". Used once per page.
  • class — a reusable style hook, e.g. class="card". Used many times.
  • data-target="24" — a custom data attribute; JavaScript reads it with getAttribute("data-target") to know what number to count up to.
  • data-m / data-y — the monthly and yearly price stored on the element itself, so the toggle only has to swap text.
  • aria-label — an accessible name for icon-only buttons (the hamburger, the close button).

  • autocomplete="off" — stops the browser from suggesting past entries inside the chat input.
Say this in the viva "data-* attributes let me store small pieces of data directly on an element instead of keeping a separate array in JavaScript. The counter and the pricing toggle both work that way."

5.4 Why the scripts are at the bottom

<script> tags sit just before </body>. The HTML is parsed first, so when the JavaScript runs, every element it looks for already exists. If the scripts were in the <head>, getElementById would return null and the page would throw errors. api.js is loaded before script.js because script.js uses the Api object defined in it.

Nine features were written by hand. Each one is a classic viva topic.

7.1 Mobile menu (event handling + classList)

CSS hides .nav-links on small screens and shows .nav-links.open. JavaScript only toggles a class — it never writes styles directly. That keeps styling in CSS.

7.2 Self-playing hero chat (setTimeout + recursion)

An array of messages is played one by one. The function calls itself with the next index after a delay, shows a typing indicator before bot messages, and restarts after the last one.

function playHeroDemo(i) {
  if (i >= heroScript.length) {           // finished → restart
    setTimeout(function () { heroChat.innerHTML = ""; playHeroDemo(0); }, 4000);
    return;
  }
  var step = heroScript[i];
  var dots = showTyping(heroChat);        // "typing..." bubble
  setTimeout(function () {
    dots.remove();
    addBubble(heroChat, step.from, step.text, step.source);
    setTimeout(function () { playHeroDemo(i + 1); }, 1400);
  }, 1100);
}

7.3 Counting numbers (setInterval + IntersectionObserver)

The numbers count up only when the section scrolls into view, which is what makes it feel alive. IntersectionObserver watches an element and fires when it becomes visible.

var observer = new IntersectionObserver(function (entries) {
  entries.forEach(function (entry) {
    if (entry.isIntersecting) {
      entry.target.querySelectorAll(".count").forEach(runCounter);
      observer.unobserve(entry.target);   // run once only
    }
  });
}, { threshold: 0.4 });                   // 40% visible
Why not use the scroll event? A scroll listener fires hundreds of times per second and must calculate positions every time. IntersectionObserver is handled by the browser itself, off the main thread, so it is far more efficient. Saying this earns marks.

7.7 Creating chat bubbles safely

function addBubble(box, from, text, source) {
  var div = document.createElement("div");
  div.className = "msg " + (from === "user" ? "msg-user" : "msg-bot");
  div.textContent = text;        // textContent, NOT innerHTML
  box.appendChild(div);
  box.scrollTop = box.scrollHeight;   // auto-scroll to the newest message
  return div;
}
Security point — a very common viva question textContent inserts the text as plain text. innerHTML would run any HTML or <script> inside it — that is an XSS (Cross-Site Scripting) hole. Since chat text comes from the user, textContent is the safe choice. The same care is taken in the leads table: the row is built with innerHTML for the fixed cells, but the user's question is inserted with row.children[1].textContent = question.

7.8 Scroll reveal

Cards start at opacity: 0; translateY(26px). A second IntersectionObserver adds the class .visible when they appear, and then stops observing that element.

7.9 localStorage (the offline fallback)

localStorage.setItem("webtiqai_kb", JSON.stringify(knowledge));
var saved = JSON.parse(localStorage.getItem("webtiqai_kb"));
  • Stores strings only, so objects go through JSON.stringify / JSON.parse.
  • Survives a refresh and even a browser restart (unlike sessionStorage).
  • Wrapped in try...catch because private mode can block it.
  • Used only when the backend is unreachable. When the server is on, the server is the single source of truth.

8. Backend — Node.js and Express

8.1 What Node.js is

JavaScript used to run only inside a browser. Node.js is a runtime built on Chrome's V8 engine that runs JavaScript on a computer directly, so it can open files, listen on a port and call other servers. It is single-threaded and event-driven: instead of waiting for a slow task (like the OpenAI call), it registers a callback and continues; when the result arrives the callback runs. That is why one Node process can serve many users.

8.2 What Express is

Express is a minimal web framework for Node. Without it you would parse URLs and methods by hand. With it, one line defines a route: 

app.get("/api/leads", function (req, res) {
  res.json(readData(FILES.leads));
});
  • req — the request object: URL, method, headers, req.body, req.params
  • res — the response object: res.json(), res.status(), res.send()

8.3 Middleware — the pipeline

Middleware is a function that runs before the route handler. Every request passes through the chain in the order the middleware was registered.

Figure 3 — The Express middleware pipeline in this project
app.use(cors());                                  // 1. allow cross-origin calls
app.use(express.json({ limit: "100kb" }));        // 2. parse JSON bodies
app.use(express.static(path.join(__dirname, ".."))); // 3. serve the website
Say this in the viva "express.static pointed one folder up means my backend also serves the frontend. So the whole project runs on a single port — http://localhost:5000 — and there is no CORS problem at all, because the page and the API share the same origin."

8.4 Environment variables (dotenv)

require("dotenv").config();                       // loads server/.env
const OPENAI_API_KEY = process.env.OPENAI_API_KEY || "";
const PORT = process.env.PORT || 5000;
  • The key is never written inside server.js, so the code can be shared safely.
  • .env is listed in .gitignore so it is never uploaded.
  • .env.example shows which variables exist, without the values.
  • The || "" and || 5000 give a safe default when a variable is missing.

8.5 Starting the server

app.listen(PORT, function () {
  console.log("Website : http://localhost:" + PORT);
});

app.listen binds to the port and keeps the process alive, waiting for requests. If the port is already used by another program, Node throws EADDRINUSE — which is exactly why this project moved from port 3000 to 5000.

9.4 Server-side validation

if (q.length < 5 || a.length < 5)
  return res.status(400).json({ error: "Both need at least 5 characters." });
if (q.length > 300 || a.length > 2000)
  return res.status(400).json({ error: "That is too long for one knowledge item." });
Why validate twice — browser AND server? Browser validation is for convenience (instant feedback, no wasted request). Server validation is for security. Anyone can bypass the browser with Postman or curl, so the server must never trust incoming data. The length limits also protect against oversized requests and a large OpenAI bill.

10. Backend — The JSON File Database

Instead of MySQL or MongoDB, three JSON files act as tables. The fs (file system) module reads and writes them.

function readData(file) {
  try {
    return JSON.parse(fs.readFileSync(file, "utf8"));
  } catch (err) {
    console.error("Could not read", file, "-", err.message);
    return [];                      // never crash the server
  }
}

function writeData(file, rows) {
  fs.writeFileSync(file, JSON.stringify(rows, null, 2), "utf8");
}
FileActs as the table forRecord shape
knowledge.jsonWhat the bot has been taught{ id, q, a, createdAt }
leads.jsonUnanswered questions{ id, question, status, time }
messages.jsonContact form submissions{ id, name, email, website, message, time }

10.1 How an id is generated

Date.now() returns the number of milliseconds since 1 January 1970. It is unique enough for a single-user project and needs no extra library. In a real system this would be an auto-increment column or a UUID.

10.2 Sync vs async file calls

readFileSync blocks the single Node thread until the file is read. For a mini project with tiny files that is perfectly fine and keeps the code simple. For a busy server you would use fs.promises.readFile with await so other requests continue meanwhile. Saying you know the difference — and why you chose the simple one — is better than pretending it is ideal.

10.3 Limitations of this approach (be honest about these)

  • No concurrency safety — two requests writing at the same moment could overwrite each other. A database handles this with transactions.
  • No querying — the whole file must be read and filtered in JavaScript.
  • No relationships — no joins between tables.
  • Does not scale — a 50 MB JSON file would be read fully for every single request.
Say this in the viva "I used JSON files on purpose so the project runs on any machine with just npm install. The read and write are wrapped in two helper functions, readData and writeData, so switching to MongoDB later would only mean rewriting those two functions — the routes would not change at all."

10.4 The files are created automatically

function ensureData() {
  if (!fs.existsSync(DATA_DIR)) fs.mkdirSync(DATA_DIR, { recursive: true });
  Object.values(FILES).forEach(function (file) {
    if (!fs.existsSync(file)) fs.writeFileSync(file, "[]", "utf8");
  });
}
ensureData();   // runs once when the server starts

This means the project works immediately after download — nothing to set up by hand.

11. The AI Layer — OpenAI API

11.1 What an API key is

An API key is a secret string (it starts with sk-) that identifies your account to OpenAI. Every request carries it in the Authorization header. OpenAI uses it to check that you are allowed in and to charge your account. If it leaks, someone else spends your credit — which is why it stays on the server, in .env, and never reaches the browser.

11.2 The Chat Completions API

const response = await fetch("https://api.openai.com/v1/chat/completions", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer " + OPENAI_API_KEY
  },
  body: JSON.stringify({
    model: "gpt-4o-mini",

11.5 The system prompt — this is the heart of the project

Figure 4 — How the rules, the content and the question are combined
const systemPrompt =
  "You are the website support assistant for " + BUSINESS_NAME + ".\n" +
  "Answer ONLY using the content below. Never invent facts, prices or policies.\n" +
  "If the answer is not in the content, reply with exactly: NO_ANSWER\n" +
  "Keep answers short (1-3 sentences) and friendly. Reply in the language the visitor used.\n\n" +
  "--- CONTENT ---\n" + content;

11.6 Why this is a simple form of RAG

RAG stands for Retrieval Augmented Generation. The idea is: first retrieve relevant information, then let the model generate an answer from it. This project does exactly that, in its simplest possible form — the whole Knowledge Base is the retrieved content. A production system (like the full AskIntel product) would first convert content into embeddings (number vectors), store them in a vector database, and retrieve only the few most similar chunks. That matters when there are thousands of documents and the prompt cannot hold them all.

Say this in the viva — a strong answer "The model is never asked to know my business. It is given the facts in the prompt and asked only to phrase them. That is why it cannot hallucinate a price. This is a basic RAG pattern; for scale I would add embeddings and a vector database so only the relevant chunks are sent."

11.7 The NO_ANSWER check

const answer = await askOpenAI(message, knowledge);

if (answer.includes("NO_ANSWER")) {
  saveLead(message);                      // store the question as a lead
  return res.json({
    reply: "Sorry, I could not find that in my content, and I will not guess...",
    answered: false, source: null, mode: "ai"
  });
}

The sentinel word NO_ANSWER turns a vague "I'm not sure" into a signal the program can act on. Not knowing becomes a feature: it creates a lead for the human team.

11.8 Error handling around the AI call

if (!response.ok) {
  const details = await response.text();
  throw new Error("OpenAI returned " + response.status + ": " + details.slice(0, 200));
}

Common failures: 401 wrong key, 429 rate limit or no credit, 500 OpenAI is down, or no internet. All of them are caught by the try...catch in the route, logged on the server, and the request quietly falls through to the offline engine instead of showing the visitor an error.

13. The Offline Matching Algorithm

When there is no API key — or OpenAI fails — the server answers using its own small algorithm. It is pure JavaScript, no AI, and it is a favourite viva topic because you can explain every line.

13.1 Step 1 — clean the text

function cleanWords(text) {
  return String(text)
    .toLowerCase()                       // "Delivery" and "delivery" are the same
    .replace(/[^a-z0-9\s]/g, " ")        // remove ? , . ! etc.
    .split(/\s+/)                        // make an array of words
    .filter(w => w.length > 1 && !STOP_WORDS.includes(w));
}

Stop words are words that carry no meaning for matching: the, is, are, do, does, you, your, what, how, can, my, to, in, on, for. Removing them stops "do you" from matching every question in the list.

13.2 Step 2 — score every knowledge item

Exact word match+2deliver = deliver
Prefix (partial) match+1deliver vs delivery
No match0—

The item with the highest total wins. If the best score is below 2, the bot says it does not know. That threshold prevents a single weak word from producing a wrong answer.

16.1 What CORS is

Cross-Origin Resource Sharing. By default a browser blocks a page from calling a different origin (different protocol, domain or port) — this is the same-origin policy, and it protects users. The cors() middleware adds the response header Access-Control-Allow-Origin so the call is permitted. It is needed here only when the HTML is opened directly from the file system; when Express serves the page, both share one origin.

Note: cors() with no options allows every origin. That is fine for a local college project, but in production you would restrict it to your own domain.

16.2 Known weaknesses (say these before the examiner finds them)

  • No authentication — anyone who can reach the server can edit the Knowledge Base. A real version needs login and sessions or JWT.
  • No rate limiting — someone could send thousands of questions and run up the OpenAI bill. express-rate-limit would fix this.
  • Open CORS — should be restricted to one domain in production.
  • JSON files, not a database — no transactions, no concurrency safety.
  • No HTTPS locally — a deployed version would need TLS so the traffic is encrypted.
Say this in the viva "I know the gaps: there is no login, no rate limiting and CORS is open. For a local demo these are acceptable, and I can name exactly what I would add before deploying — authentication, rate limiting, a real database and HTTPS."

PART B — VIVA QUESTION BANK

20. Section 1 — About the Project

Answer in 2–3 sentences. Short and confident beats long and vague.

Q1. Explain your project in one minute.
WebtiqAI is an AI chatbot that a business embeds on its website. The owner types the business information — prices, timings, policies — into a Knowledge Base. When a visitor asks a question, my frontend sends it to my Node.js server, which builds a prompt containing those facts and asks the OpenAI model to answer using only that content. If the answer is not in the content, the bot admits it and the question is saved as a lead for the human team. The frontend is plain HTML, CSS and JavaScript; the backend is Node.js with Express.
Q2. What problem does it solve?
Small businesses cannot keep a person on live chat 24 hours a day, so visitors who ask a simple question at night get no reply and leave. This bot answers instantly at any hour, and never loses the question even when it does not know the answer.
Q3. What makes it different from ChatGPT?
ChatGPT answers from general knowledge and can invent details about my business. My bot is restricted to the business's own content through the system prompt and must reply NO_ANSWER when the content does not cover the question. It is a grounded, business-specific assistant rather than a general one.
Q4. Which part was the hardest?
Making the bot refuse to answer. A language model naturally tries to be helpful and fills gaps. I had to write the system prompt so that "not in the content" produces an exact sentinel word, NO_ANSWER, which my code can detect reliably and turn into a lead.
Q5. Why did you build a backend instead of calling the API from JavaScript in the page?
Because the API key would then sit in a file the visitor can open with Ctrl+U. Anyone could copy it and spend my OpenAI credit. The key must stay on the server. The server also lets me validate input, store data and control the prompt.
Q6. How many pages does the site have and what are they?
Two. index.html is the landing page — hero, stats, features, how it works, bot team, pricing, FAQ and contact. demo.html is the working demo where you train a bot and chat with it, with a leads table below.
Q7. What are the four "bots" on your landing page?
They are a friendly way to describe the pipeline for non-technical users. The Manager routes the question, the Receptionist finds the answer, the Checker verifies it and shows the source, and the Crawler learns new content. Technically they are stages of one request, not four programs.
Q8. How long did it take and how did you plan it?
I built it in three layers: first the static HTML and CSS, then the JavaScript interactions, then the backend and the AI call. Keeping the frontend working on its own meant I always had something demonstrable.
Q9. How do you run the project?
cd server, then npm install once, then npm start, and open http://localhost:5000. The backend also serves the website, so no Live Server is needed.
Q10. What would you improve with more time?
Login so multiple businesses can use it, a real database, conversation memory for follow-up questions, and proper RAG with embeddings so only the relevant content is sent instead of the whole Knowledge Base.
Q11. Is this project original?
The idea is based on an existing product concept — an embeddable support chatbot — but all the code here is written from scratch: the layout, the interactions, the API and the prompt design.
Q12. Who is the target user?
Small and medium businesses with a website and no support team — a shop, a clinic, a coaching centre, a local service. People who cannot afford live chat agents but lose customers without them.

21. Section 2 — HTML

Q13. What are semantic tags and which have you used?
Tags that describe the meaning of the content, not its appearance. I used header, nav, section, article, form, table and footer. They help screen readers and search engines understand the page.
Q14. Difference between id and class?
id is unique — one element per page, used as a JavaScript hook like getElementById("contactForm"). class can repeat and is mainly for styling, like .card on six different cards.
Q15. What is a data-* attribute? Show one from your project.
A custom attribute for storing data on an element. My counters use data-target="24" and JavaScript reads it with getAttribute("data-target") to know the final number. The pricing cards store both prices as data-m and data-y.
Q16. Why are your script tags at the bottom of the body?
So the HTML is parsed before the JavaScript runs. Otherwise document.getElementById would return null because the elements do not exist yet. It also lets the page render first, which feels faster.
Q17. What does the viewport meta tag do?
<meta name="viewport" content="width=device-width, initial-scale=1"> tells a phone to use its real width instead of pretending to be a desktop. Without it the media queries would never trigger and the site would look zoomed out.
Q18. What is novalidate and why did you use it?
It switches off the browser's built-in form validation popups so that my own JavaScript validation runs and shows my styled error messages under each field.
Q19. What is the difference between <div> and <section>?
div has no meaning — it is a generic container used for styling. section means a thematic block of content that usually has a heading. I used section for the main page blocks and div only for layout wrappers.
Q20. What is aria-label for?
Accessibility. My hamburger and close buttons contain only an icon, so a screen reader would read nothing. aria-label="Open menu" gives them a spoken name.
Q21. Why did you use a <table> for the leads but not for the layout?
Tables are for tabular data — rows and columns that belong together, like leads with an id, question, status and time. Using tables for page layout is outdated and bad for accessibility; CSS Grid and Flexbox do that job.
Q22. What happens if JavaScript is disabled?
The page still renders completely — all the content and styling are in the HTML and CSS. The interactive parts stop working: the chat, the accordion, the counters and the pricing toggle. The content remains readable, which is the point of keeping structure separate from behaviour.

22. Section 3 — CSS

Q23. Flexbox vs Grid — when do you use which?
Flexbox is one-dimensional: a row or a column. I used it for the navbar, the button row and the stack of chat bubbles. Grid is two-dimensional: rows and columns together. I used it for the card grids, the three steps, the pricing cards and the two-column demo layout.
Q24. What are CSS variables and why use them?
Custom properties declared in :root, like --brand: #6c4df6, and used with var(--brand). Changing one line changes every button, link and accent on the site. Without them I would have to find and replace the colour in dozens of places.
Q25. Explain the box model.
Every element is content, then padding, then border, then margin. I set box-sizing: border-box globally so that width includes padding and border — which makes layout maths predictable.
Q26. Difference between position: fixed, absolute and relative?
relative offsets an element from its normal spot and becomes a reference for children. absolute positions relative to the nearest positioned ancestor and leaves the flow. fixed positions relative to the viewport and stays put while scrolling — my navbar and chat button use it.
Q27. What is z-index? Where did you need it?
It controls stacking order for positioned elements. The navbar is z-index: 100 so content scrolls under it, and the chat widget is 200 so it stays above the navbar.
Q28. What is a media query? Give yours.
CSS that applies only under a condition, usually screen width. I have @media (max-width: 980px) for tablets, which collapses the hero and card grids to two columns, and @media (max-width: 680px) for phones, which shows the hamburger menu and makes everything a single column.
Q29. Difference between transition and animation?
A transition animates between two states and needs a trigger such as hover — my buttons lift that way. An animation with @keyframes runs on its own and can loop — my typing dots and the pulsing online dot use that.
Q30. Why animate max-height for the FAQ instead of height?
CSS cannot transition to height: auto. I animate max-height instead and set it in JavaScript to answer.scrollHeight + "px", which is the real content height, so the accordion opens smoothly whatever the text length.
Q31. Why use transform instead of changing top or left?
transform is GPU-accelerated and does not trigger layout recalculation, so the animation stays smooth. Changing top forces the browser to re-layout the page on every frame.
Q32. What does the CSS specificity order look like?
Inline style beats id, id beats class, class beats element selector. When two rules have the same specificity, the later one wins. I avoided !important entirely by keeping the selectors simple.
Q33. How did you create the hard shadow look?
box-shadow: 5px 5px 0 #1f1b2d — an offset with zero blur, so it reads as a solid block rather than a soft glow. On hover the card moves up-left with translate(-3px, -3px) and the shadow grows, which makes it look lifted.
Q34. What is the difference between em, rem, % and px?
px is fixed. em is relative to the parent's font size and can compound. rem is relative to the root font size, so it is predictable — I used it for headings. % is relative to the parent's size, used for widths.

23. Section 4 — JavaScript

Q35. What is the DOM?
The Document Object Model — the browser's tree representation of the HTML page. JavaScript reads and changes that tree, and the browser repaints. Every chat bubble in my project is a node I create and append.
Q36. Difference between innerHTML and textContent? Which did you use and why?
innerHTML parses the string as HTML, so a <script> inside it could run — that is an XSS risk. textContent inserts plain text. All user-typed text in my project goes through textContent, including the chat bubbles and the lead question cell.
Q37. What does e.preventDefault() do?
It stops the browser's default action. On a form submit the default is to reload the page, which would wipe the chat. I prevent it and handle the submission with JavaScript instead.
Q38. Difference between setTimeout and setInterval?
setTimeout runs a function once after a delay — I use it for the typing pause before a bot reply. setInterval repeats until cleared — I use it for the counting numbers and call clearInterval when the target is reached.
Q39. What is IntersectionObserver and why is it better than a scroll listener?
It watches whether an element is visible in the viewport and calls back when that changes. A scroll listener fires continuously and must measure positions each time; the observer is handled by the browser internally, so it is much more efficient. I use it for the counters and the card reveal animation, and call unobserve so each animation runs only once.
Q40. What is event bubbling?
An event fires on the element and then travels up through its ancestors. It is why a click on the span inside a button also triggers the button's listener. It also enables event delegation — attaching one listener to a parent instead of many to children.
Q41. What is a callback function?
A function passed into another function to be called later. Every addEventListener handler and every setTimeout function in my project is a callback.
Q42. What is a Promise? How is it used in your project?
An object representing a value that will be available later, with .then() for success and .catch() for failure. fetch() returns a Promise, so every API call in api.js is promise-based — for example Api.chat(q).then(showReply).catch(showError).
Q43. What is the difference between async/await and .then()?
They do the same thing with different syntax. await makes asynchronous code read like normal top-to-bottom code and uses try...catch for errors. My backend uses async/await for the OpenAI call; my frontend uses .then() chains.
Q44. Explain fetch() in your own words.
It sends an HTTP request and returns a Promise for the response. I pass the method, the Content-Type header and a JSON string body, then call response.json() to read the reply. I also check response.ok, because fetch does not throw on a 400 or 500 — it only rejects on a network failure.
Q45. What is localStorage? What are its limits?
Browser storage of key-value string pairs that survives refreshes and restarts, about 5 MB, per origin. It stores strings only, so I use JSON.stringify and JSON.parse. It is not secure and not shared with the server, so I use it only as an offline fallback.
Q46. Difference between localStorage, sessionStorage and cookies?
localStorage persists until cleared. sessionStorage is wiped when the tab closes. Cookies are smaller, are sent to the server with every request, and can have an expiry — used for sessions and authentication.
Q47. Explain your email validation regex.
/^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/ — one or more characters that are not a space or @, then an @, then more such characters, then a literal dot, then at least two characters. ^ and $ anchor it to the whole string so nothing extra is allowed.
Q48. Difference between var, let and const?
var is function-scoped and hoisted. let and const are block-scoped; const cannot be reassigned, though an object it points to can still be mutated. My frontend uses var deliberately for maximum browser compatibility without a build step; my backend uses const.
Q49. What do map, filter and forEach do?
forEach runs a function for each item and returns nothing — I use it to render the knowledge list. map returns a new transformed array — I use it to build the numbered content list for the prompt. filter returns the items that pass a test — I use it to remove a deleted item and to drop stop words.
Q50. How does your auto-playing hero chat work?
An array of message objects, and a function playHeroDemo(i) that shows message i, then calls itself with i + 1 inside a setTimeout. Bot messages get a typing indicator first. When the index passes the end of the array, it clears the box and restarts from zero.

24. Section 5 — Node.js, Express and the Backend

Q51. What is Node.js?
A runtime that lets JavaScript run outside the browser, built on Chrome's V8 engine. It can read files, listen on a port and call other servers. It is single-threaded and event-driven, so slow work is handled with callbacks instead of blocking.
Q52. What is Express and why use it?
A minimal web framework for Node. Without it I would parse URLs and HTTP methods manually. With it, app.post("/api/chat", handler) defines a route in one line, and middleware handles JSON parsing and static files.
Q53. What is middleware? Name the ones you used.
A function that runs on every request before the route handler. I use three: cors() to allow cross-origin calls, express.json() to parse the request body into req.body, and express.static() to serve my HTML, CSS and JS files.
Q54. What are req and res?
The request and response objects. req carries what the client sent — req.body, req.params, req.query, headers. res sends the answer back — res.json(), res.status(), res.send().
Q55. What is REST?
An architectural style where the URL identifies a resource and the HTTP method says what to do with it. GET /api/knowledge reads, POST /api/knowledge creates, DELETE /api/knowledge/:id removes. It is stateless — every request carries everything it needs.
Q56. What does :id mean in a route?
A route parameter. app.delete("/api/knowledge/:id", ...) matches any value in that position and makes it available as req.params.id. I convert it with Number() because URL parameters always arrive as strings.
Q57. Which status codes do you return and when?
200 for a successful read or chat, 201 when something is created like a knowledge item or a contact message, 400 when validation fails, 404 when deleting an id that does not exist, and 500 for an unexpected server error.
Q58. Why validate on the server when the browser already validates?
Browser validation is only for user convenience and can be bypassed completely with Postman, curl or the devtools console. The server must never trust incoming data, so every route checks length and format again.
Q59. How does your server store data?
Three JSON files in server/data/, read and written with the fs module through two helpers, readData and writeData. The folder and files are created automatically on first start.
Q60. Why not a real database?
For a mini project a file keeps setup at zero — npm install and it runs on any machine. I know the limits: no transactions, no concurrent-write safety and no querying. Because all file access goes through two functions, switching to MongoDB would only change those two functions.
Q61. What is dotenv and why is it needed?
It loads key-value pairs from a .env file into process.env. It keeps the secret API key out of the source code, so the code can be shared or uploaded without leaking the key. .env is listed in .gitignore.
Q62. What is CORS and why did you need it?
Cross-Origin Resource Sharing. Browsers block a page from calling a different origin by default. The cors() middleware adds the header that permits it. I need it only when the HTML is opened directly as a file; when Express serves the page, both share one origin.
Q63. What does express.static do here?
It serves the folder one level above server/, which is my website. So the backend serves the frontend and the whole project runs on one port with no CORS issue at all.
Q64. Your server runs on port 5000 — why not 3000?
3000 was already in use on my machine by another application, so Node threw EADDRINUSE. The port is read from process.env.PORT with 5000 as the default, so it can be changed in .env without touching the code.

25. Section 6 — API, AI and Prompt Engineering

Q65. What is an API key and how do you protect it?
A secret string that identifies my OpenAI account and is billed for each request. It lives only in server/.env, is read through process.env, is never sent to the browser, and .env is in .gitignore so it is never uploaded.
Q66. Which OpenAI endpoint and model do you use?
The Chat Completions endpoint, https://api.openai.com/v1/chat/completions, with the model gpt-4o-mini — the small, fast and cheap model, which is enough because the facts are already supplied in the prompt.
Q67. Explain the three message roles.
system sets the rules and the content the model must stick to. user is the visitor's question. assistant would be the model's earlier replies — I do not send those, so each question is independent.
Q68. What is temperature? What value did you choose and why?
It controls randomness, from 0 to 2. I use 0.2 so the answers are consistent and factual. A support bot must repeat the same fact the same way; creativity would be a bug here.
Q69. What is a token and why limit max_tokens?
A token is a chunk of text the model processes, roughly three-quarters of a word. Billing is per token. I cap the reply at 200 tokens so a reply stays short and a single request can never produce a large bill.
Q70. What is prompt engineering? Show yours.
Designing the instruction so the model behaves the way the application needs. My system prompt says: you are the assistant for this business; answer ONLY from the content below; never invent facts; if the answer is not there reply exactly NO_ANSWER; keep it to one to three sentences; reply in the visitor's language. Then the whole Knowledge Base is appended.
Q71. What is hallucination and how do you prevent it?
When a model states something confidently that is not true. I prevent it by never asking the model to recall facts — I give it the facts in the prompt and restrict it to them, and I give it a legal way out, NO_ANSWER, so admitting ignorance is easier than inventing.
Q72. What is RAG? Is your project RAG?
Retrieval Augmented Generation — retrieve relevant content first, then let the model generate an answer from it. Mine is the simplest form: the retrieval step is "send the whole Knowledge Base". A full implementation would use embeddings and a vector database to fetch only the closest chunks.
Q73. What is an embedding?
Text converted into a list of numbers that captures meaning, so two texts can be compared mathematically by the distance between their vectors. It is how a real RAG system finds the most relevant content without matching exact words.
Q74. What happens if the OpenAI call fails?
The try...catch around it logs the real error on the server and the code falls through to the offline matching engine, so the visitor still gets an answer. Typical causes are a wrong key (401), no credit or rate limiting (429), or no internet.
Q75. How do you know which knowledge item the answer came from?
After the model replies, the server runs the local matching function to find the closest knowledge item and returns its question as the source field. The chat bubble shows it as "Source: ..." so the user can verify the answer. That is the Checker bot's job on the landing page.
Q76. Why two chat endpoints, /api/chat and /api/site-chat?
They use different content. /api/chat answers from the business Knowledge Base in the JSON file, which the user edits. /api/site-chat answers from a fixed array inside server.js about WebtiqAI itself, for the floating widget on the landing page.
Q77. Does your bot remember the previous message?
No — it is stateless. Each question is sent on its own. To add memory I would keep the last few turns and send them as assistant and user messages, which would make follow-ups like "and to Delhi?" work.
Q78. What does the API cost?
Billing is per token, both input and output. gpt-4o-mini is the cheapest current option, and my prompts are small, so a demo costs a tiny fraction of a rupee per question. The 200-token cap keeps the upper bound fixed.

26. Section 7 — Tricky and Scenario Questions

These separate students who understand the project from students who memorised it.

Q79. I will turn off the internet. Will your project still work?
Yes. The OpenAI call will fail, the try...catch catches it, and the server answers with its own word-matching engine. The site keeps working and the badge shows the mode honestly. Only the quality of the answer drops.
Q80. I will stop your server. What happens then?
The health check fails, Api.online becomes false, the badge turns red, and both pages switch to browser mode: matching runs in JavaScript and the Knowledge Base comes from localStorage. The page never shows an error screen.
Q81. Someone types <script>alert(1)</script> in your chat. What happens?
It appears as plain text, because every bubble is filled with textContent, not innerHTML. The script never executes. That is deliberate XSS protection.
Q82. What if someone sends a 10,000-character question?
The route rejects anything over 500 characters with a 400 response, and express.json({ limit: "100kb" }) rejects an oversized body before it even reaches my code. Both protect the server and the API bill.
Q83. Why did you keep a word-matching algorithm when you have AI?
Three reasons: the demo must survive with no key, no credit or no internet; it is a sensible fallback when the API fails; and it is also how the server identifies the source item for the AI answer. It also lets me show that I can write the logic myself, not only call an API.
Q84. Your bot answered something wrong. Whose fault is it?
Usually the Knowledge Base — if the content is wrong or missing, the answer will be wrong or refused. The bot is restricted to the given content by design, so content quality decides answer quality. That is exactly why the source is shown with every answer: the owner can see where it came from and fix it.
Q85. Can two people use this at the same time?
They can chat at the same time, since each request is independent. But they share one Knowledge Base, and two simultaneous writes to the same JSON file could overwrite each other. Fixing that properly needs user accounts and a real database.
Q86. Show me where the API key is used in your code.
In server.js: const OPENAI_API_KEY = process.env.OPENAI_API_KEY at the top, and inside askOpenAI() in the header "Authorization": "Bearer " + OPENAI_API_KEY. Nowhere else, and never in any file the browser downloads.
Q87. What is the difference between your project and a simple if-else chatbot?
An if-else bot only matches fixed phrases it was programmed with. Mine understands meaning — "can I get it at my house?" is answered from content that says "home delivery", with no shared keywords. It also handles other languages and spelling mistakes, and it is driven by data the user types rather than by code.
Q88. If I asked you to add login right now, how would you do it?
Add a users file or table with hashed passwords using bcrypt, a POST /api/login route that returns a JWT, an auth middleware that checks the token on every /api/knowledge route, and an ownerId field on each knowledge item so each business sees only its own content.

28. Last-Minute Revision Sheet

If you read nothing else, read this page before walking in.

The 30-second pitch "WebtiqAI is an embeddable AI chatbot for business websites. The owner trains it on their own content. My Node.js backend builds a prompt containing that content and asks OpenAI to answer using only those facts. If the answer is not there, the bot says so honestly and the question becomes a lead. Frontend is plain HTML, CSS and JavaScript; backend is Node with Express; storage is JSON files."

The five facts you must not fumble

  1. Why a backend? To hide the API key. In the browser it would be public.
  2. How is hallucination stopped? The system prompt restricts the model to the given content and requires NO_ANSWER when it is not there.
  3. What happens when it does not know? It admits it and saves a lead.
  4. What if the internet or server fails? It falls back — server-side word matching, then browser-side localStorage. Three modes, shown by a badge.
  5. Why textContent? To prevent XSS from user-typed chat text.
